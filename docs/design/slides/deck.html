Current State · The Problem

Today's cycle is manual and siloed.

Requirements live in scattered docs. Tickets are hand-written. Agents are hand-built per project, skills wired ad-hoc with no security check — and nothing links a requirement to the code that shipped.

New State · Four Phases

A guided, composable, audited lifecycle.

Ideate

  • Gather: Glean · Confluence · docs

Build

  • agent.yaml manifest (spine)
  • Scaffold via CLI

Govern

  • SkillSpector security gate
  • Eval gate before "done"
  • Audited on the CLI
04

Run

  • Deploy / run the agent
  • Observe & track
  • Feed learnings back

↻ Run → Ideate — outcomes feed the next requirement. The CLI audits every phase.

Current Architecture · Drift

Logic drifted into the dashboard.

Shipping fast pushed engine logic and state into the dashboard — a parallel implementation. CLI users and CI didn't benefit, and there was no shared audit.

Dashboard — grew its own engine
React UI FastAPI backend manifest logic security scan retriever store
▲ CLI users & CI miss security · manifest · retrievers
CLI (agentic-cli)
templates · onboard · skills tracker (activity only)

Duplicated logic · dashboard-only capabilities · the manifest understood only by the browser

New Architecture · CLI-First

CLI is the engine and the auditor.

Engine logic lives in the CLI. Every surface — dashboard, CI, terminal — calls it. The tracker becomes the audit trail, tagged by origin and linkable across features.

Surfaces
Dashboard UI· CI / automation· CLI users → delegate to CLI
CLI (agentic-cli) — engine + auditor
manifest skill_security retrievers templates · onboard · eval ▣ audit trail · correlation_id · source
External — via dashboard
MCP · GleanConfluence JiraBitbucket

CLI owns logic + audit  ·  dashboard owns UX, visualization & MCP calls
